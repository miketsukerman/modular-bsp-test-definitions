# npu (`adv-npu`)

NPU checks: configured NPU character device nodes exist and are
readable/writable, and each configured bus controller is present on the target.

* **Definition:** [`automated/linux/npu/npu.yaml`](../../automated/linux/npu/npu.yaml)
* **Script:** [`automated/linux/npu/npu.sh`](../../automated/linux/npu/npu.sh)

## Scope

**Covered**

* Each configured `NPU{N}_DEV` exists as a readable/writable character device.
* Optional controller discovery through `chk_bus`: PCI devices are matched with
  `lspci`; SoC devices are matched below `/sys/devices/platform/` using the bus
  ID, device type, node name, and device basename.

**Not covered**

* Running an inference workload or validating NPU performance.
* Driver-specific health, firmware, model-loading, or accelerator API checks.

## Prerequisites

* **Hardware:** an NPU exposed by the board BSP at each configured device node.
* **Target tools:** `lspci` is required only for instances whose bus is `pci`.
  SoC checks use standard shell tools and sysfs.
* **Root:** usually required, because `NPU{N}_DEV` must be readable and writable.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `NPU_COUNT` | `"1"` | Number of NPU devices to iterate over (`npu0` … `npu<COUNT-1>`) |
| `NPU{N}_DEV` | `""` | Character device node for NPU `N`, for example `/dev/galcore`; empty = device-node check not emitted |
| `NPU{N}_BUS` | `"soc"` | Bus type for NPU `N` (`soc` or `pci`) |
| `NPU{N}_BUS_ID` | `""` | Bus address/ID; empty = controller check not emitted |
| `NPU{N}_BUS_DEVICE_TYPE` | `""` | SoC sysfs device type used by `chk_bus` |
| `NPU{N}_BUS_NODE_NAME` | `""` | SoC sysfs node-name suffix used by `chk_bus` |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

Only `NPU_COUNT` is unconditional. Per-instance checks are emitted only when
that instance supplies the fields required by the script.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `npu<N>` for instance
`N`.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-NPU-DEV-${label}` | | `NPU{N}_DEV` exists and is a readable/writable character device | Node missing, wrong type, or not R/W | Not emitted when `NPU{N}_DEV` is empty |
| `L-NPU-CONTROLLER-${label}` | | `chk_bus` finds the configured PCI or SoC controller | Controller not found, unsupported bus type, or required lookup fields do not match | Not emitted when `NPU{N}_BUS` or `NPU{N}_BUS_ID` is empty |

## Running locally

```sh
cd automated/linux/npu
NPU_COUNT=1 \
NPU0_DEV=/dev/galcore \
NPU0_BUS=soc \
NPU0_BUS_ID=38300000 \
NPU0_BUS_DEVICE_TYPE=npu \
NPU0_BUS_NODE_NAME=galcore \
bash npu.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for emitted
`L-NPU-DEV-*` and `L-NPU-CONTROLLER-*` checks, each ending in a `RESULT:` line.
LAVA surfaces these logs alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-NPU-DEV-*` fails | Wrong node path, driver not loaded, or the test is not running with access to the character device |
| `L-NPU-CONTROLLER-*` fails on PCI | `NPU{N}_BUS_ID` does not match `lspci` output, or `lspci` is missing |
| `L-NPU-CONTROLLER-*` fails on SoC | Bus ID, device type, node name, or device-node basename does not match the platform sysfs layout |
| `L-NPU-DEV-*` missing | `NPU{N}_DEV` was left empty |
