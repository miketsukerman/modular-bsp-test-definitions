# optee (`adv-optee`)

OP-TEE checks: the configured TEE character device exists and is
readable/writable, then the `xtest` regression suite runs in quick or full mode.

* **Definition:** [`automated/linux/optee/optee.yaml`](../../automated/linux/optee/optee.yaml)
* **Script:** [`automated/linux/optee/optee.sh`](../../automated/linux/optee/optee.sh)

## Scope

**Covered**

* Optional `OPTEE_DEV` character device presence and read/write access.
* `xtest` regression execution. By default the script runs `xtest 1001`; with
  `OPTEE_FULL_TEST=1` it runs `xtest` without an argument.

**Not covered**

* Secure-world provisioning, key state, or Trusted Application coverage beyond
  what `xtest` itself exercises.
* OP-TEE performance, boot-log parsing, or firmware version validation.

## Prerequisites

* **Hardware:** OP-TEE enabled in firmware and a kernel TEE device when
  `OPTEE_DEV` is set.
* **Target tools:** `xtest` for the functional regression case; if absent the
  `xtest` case is emitted as `skip`.
* **Root:** usually required for read/write access to `/dev/tee*` and for some
  `xtest` operations.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `OPTEE_DEV` | `/dev/tee0` | TEE character device node; empty = device-node check not emitted |
| `OPTEE_FULL_TEST` | `"0"` | `"0"` runs quick `xtest 1001`; `"1"` runs the full `xtest` suite |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

If `OPTEE_DEV` is set and fails the device check, the script exits without
emitting the `xtest` result.

## Test cases

IDs are shown in sanitised (LAVA) form.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-OPTEE-DEV` | | `OPTEE_DEV` exists and is a readable/writable character device | Node missing, wrong type, or not R/W; `xtest` is not attempted afterwards | Not emitted when `OPTEE_DEV` is empty |
| `L-OPTEE-XTEST-F` | ✓ | `xtest` exits with status `0` | `xtest` exits non-zero | `skip` when `xtest` is not installed; not emitted if `L-OPTEE-DEV` failed |

## Running locally

```sh
cd automated/linux/optee
OPTEE_DEV=/dev/tee0 \
OPTEE_FULL_TEST=0 \
bash optee.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for emitted
`L-OPTEE-DEV` and `L-OPTEE-XTEST-F` checks. The `xtest` log contains only the
last 50 output lines, followed by a `RESULT:` line. LAVA surfaces these logs
alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-OPTEE-DEV` fails | OP-TEE driver not loaded, wrong `OPTEE_DEV`, or insufficient permissions |
| `L-OPTEE-XTEST-F` is skipped | `xtest` is not installed on the target image |
| `L-OPTEE-XTEST-F` fails in quick mode | The `xtest 1001` regression failed; rerun with `VERBOSE=1` and inspect the captured tail |
| Full run is very slow | `OPTEE_FULL_TEST=1` runs the entire `xtest` suite |
