# i2c (`adv-i2c`)

I2C bus checks: `/dev/i2c-N` device node presence and read/write access, plus
optional controller-name matching from `i2cdetect -l`.

* **Definition:** [`automated/linux/i2c/i2c.yaml`](../../automated/linux/i2c/i2c.yaml)
* **Script:** [`automated/linux/i2c/i2c.sh`](../../automated/linux/i2c/i2c.sh)

## Scope

**Covered**

* Each configured `/dev/i2c-N` node exists and is a readable/writable character
  device.
* Optional controller name lookup in `i2cdetect -l` for each configured bus.

**Not covered**

* Scanning bus addresses or probing attached devices.
* I2C transfer/read/write transactions.
* Electrical validation, bus speed, pull-ups, arbitration or clock-stretching.

## Prerequisites

* **Hardware:** configured I2C controller nodes must be present. No attached I2C
  peripheral is required.
* **Target tools:** `i2cdetect` from i2c-tools is needed for controller-name
  checks; if absent those checks are skipped.
* **Root:** usually required for read/write access to `/dev/i2c-*`, depending on
  target device-node permissions.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `I2C_COUNT` | `"1"` | Number of I2C buses to iterate over (`i2c0` … `i2c<COUNT-1>`) |
| `I2C{N}_DEV` | `/dev/i2c-0` | Character device node for bus `N` |
| `I2C{N}_CONTROLLER` | `""` | Expected controller name from `i2cdetect -l`; empty = controller check not emitted |
| `I2C{N}_REFERENCE` | `""` | Human reference from board configuration; informational only and not read by `i2c.sh` |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

Only `I2C{N}_DEV` is mandatory per bus. `I2C{N}_REFERENCE` is generated into
the YAML parameters but has no effect on emitted test cases.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `i2c<N>` for bus `N`.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-I2C-DEV-${label}` | | Device node exists and is a readable/writable char device | Node missing or not R/W (remaining checks for this bus are abandoned) | — |
| `L-I2C-CONTROLLER-${label}` | | `i2cdetect -l` has a line for the device and expected controller text | Matching line or controller text is not found | Skip when `i2cdetect` is missing; not emitted when `I2C{N}_CONTROLLER` is empty |

## Running locally

```sh
cd automated/linux/i2c
I2C_COUNT=1 \
I2C0_DEV=/dev/i2c-0 \
I2C0_CONTROLLER="i.MX I2C adapter" \
bash i2c.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for the device
node and controller checks, including raw `i2cdetect -l` output for
`L-I2C-CONTROLLER-*`, and each log ends in a `RESULT:` line. LAVA surfaces
these logs alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-I2C-DEV-*` fails | Wrong node path, missing kernel adapter, or insufficient permissions |
| `L-I2C-CONTROLLER-*` skips | `i2cdetect` from i2c-tools is not installed on the target |
| `L-I2C-CONTROLLER-*` fails | Expected controller text does not match `i2cdetect -l`; run it on the target and copy the actual name |
| No controller result appears | `I2C{N}_CONTROLLER` is empty |
