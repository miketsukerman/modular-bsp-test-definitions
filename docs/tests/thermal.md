# thermal (`adv-thermal`)

Thermal checks: configured thermal-zone sysfs entry presence and current
reported temperature inside the configured minimum and maximum Celsius bounds.

* **Definition:** [`automated/linux/thermal/thermal.yaml`](../../automated/linux/thermal/thermal.yaml)
* **Script:** [`automated/linux/thermal/thermal.sh`](../../automated/linux/thermal/thermal.sh)

## Scope

**Covered**

* `/sys/class/thermal/<zone>/temp` exists for every configured thermal zone.
* The current temperature, read in millidegrees Celsius and converted to whole
  Celsius, is greater than or equal to `TZ{N}_MIN`.
* The current temperature is less than or equal to `TZ{N}_MAX`.
* The measured temperature is emitted as a LAVA metric in degrees Celsius.

**Not covered**

* Thermal trip points, cooling devices, fan control, throttling behaviour, or
  sensor calibration.
* Stress or heat-up/cool-down behaviour over time; only one instantaneous
  temperature sample is read.

## Prerequisites

* **Hardware:** none beyond the thermal sensors exposed by the kernel.
* **Target tools:** standard shell utilities only (`cat` and arithmetic in
  `bash`).
* **Root:** not normally required; the thermal `temp` files must be readable by
  the test user.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `THERMAL_COUNT` | `"1"` | Number of thermal zones to iterate over (`tz0` … `tz<COUNT-1>`) |
| `TZ{N}_DEV` | `thermal_zone0` | sysfs name under `/sys/class/thermal/` for zone `N` |
| `TZ{N}_MIN` | `"10"` | Minimum expected temperature in °C; script fallback is `0` if unset |
| `TZ{N}_MAX` | `"95"` | Maximum expected temperature in °C; script fallback is `100` if unset |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

`TZ{N}_DEV` is mandatory for each configured zone. If the zone path is missing,
the min/max/metric checks for that zone are not emitted.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `tz<N>` for zone `N`.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-THERMAL-ZONE-DEV-${label}` | | `/sys/class/thermal/<zone>/temp` exists | `temp` file missing | — |
| `L-THERMAL-ZONE-MIN-${label}` | | Current temperature is at least `TZ{N}_MIN` | Temperature is below the minimum | Not emitted when the zone check failed |
| `L-THERMAL-ZONE-MAX-${label}` | | Current temperature is at most `TZ{N}_MAX` | Temperature is above the maximum | Not emitted when the zone check failed |
| `L-THERMAL-ZONE-TEMP-${label}` | | Metric emitted with the current temperature in °C | Not emitted as `fail` by the script | Not emitted when the zone check failed |

## Running locally

```sh
cd automated/linux/thermal
THERMAL_COUNT=1 \
TZ0_DEV=thermal_zone0 \
TZ0_MIN=10 \
TZ0_MAX=95 \
bash thermal.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for
`L-THERMAL-ZONE-DEV-*` and `L-THERMAL-ZONE-TEMP-*`, including the raw millidegree
reading, converted Celsius value, configured range, and a `RESULT:` line for the
metric. LAVA surfaces these logs alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-THERMAL-ZONE-DEV-*` fails | Wrong `TZ{N}_DEV`, thermal driver missing, or sensor not exposed under `/sys/class/thermal` |
| `L-THERMAL-ZONE-MIN-*` fails | Sensor is reporting below the configured lower bound, or `TZ{N}_MIN` is too high for the environment |
| `L-THERMAL-ZONE-MAX-*` fails | Board is too hot, cooling is insufficient, or `TZ{N}_MAX` is too low |
| `L-THERMAL-ZONE-TEMP-*` missing | The thermal-zone `temp` file was missing, so subsequent checks were abandoned |
