# audio (`adv-audio`)

Audio checks: playback and capture device enumeration with `aplay -l` and
`arecord -l`, matching configured card names, controller prefixes, and codec
names. Functional playback and recording are present as skip stubs because they
require physical loopback wiring.

* **Definition:** [`automated/linux/audio/audio.yaml`](../../automated/linux/audio/audio.yaml)
* **Script:** [`automated/linux/audio/audio.sh`](../../automated/linux/audio/audio.sh)

## Scope

**Covered**

* Configured playback devices are listed by `aplay -l` with the expected card,
  controller prefix, and codec.
* Configured capture devices are listed by `arecord -l` with the expected card,
  controller prefix, and codec.
* Functional playback and recording requirement IDs are emitted as skips.

**Not covered**

* Actual audio playback, capture, or loopback validation.
* `AUDIO_*_DEV_ID` matching; the parameter is defined and generated, but the
  current script does not consume it.
* Electrical validation of jacks, codecs, speakers, or microphones.

## Prerequisites

* **Hardware:** configured audio playback/capture devices must be present.
  Functional audio needs physical loopback wiring, but automated runs skip it.
* **Target tools:** `aplay` for playback enumeration and `arecord` for capture
  enumeration. Missing tools cause the corresponding device checks to skip.
* **Root:** not required by the script.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `AUDIO_PLAYBACK_COUNT` | `"0"` | Number of playback devices to iterate over (`pb0` … `pb<COUNT-1>`) |
| `AUDIO_CAPTURE_COUNT` | `"0"` | Number of capture devices to iterate over (`cap0` … `cap<COUNT-1>`) |
| `AUDIO_PB{N}_CARD` | `""` | Expected playback card name from `aplay -l` for playback device `N` |
| `AUDIO_PB{N}_CONTROLLER` | `""` | Expected playback controller prefix before `:` in the `aplay -l` entry |
| `AUDIO_PB{N}_DEV_ID` | `""` | Expected playback device sub-id; currently not consumed by `audio.sh` |
| `AUDIO_PB{N}_CODEC` | `""` | Expected playback codec name from `aplay -l` |
| `AUDIO_CAP{N}_CARD` | `""` | Expected capture card name from `arecord -l` for capture device `N` |
| `AUDIO_CAP{N}_CONTROLLER` | `""` | Expected capture controller prefix before `:` in the `arecord -l` entry |
| `AUDIO_CAP{N}_DEV_ID` | `""` | Expected capture device sub-id; currently not consumed by `audio.sh` |
| `AUDIO_CAP{N}_CODEC` | `""` | Expected capture codec name from `arecord -l` |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

Only the count parameters control iteration. For each iterated device, empty
card or codec values make the corresponding enumeration check fail rather than
skip.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `pb<N>` for playback
and `cap<N>` for capture.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-AUDIO-PLAYBACK-DEV-${label}` | | `aplay -l` contains an entry whose card and codec match `AUDIO_PB{N}_CARD` and `AUDIO_PB{N}_CODEC`, and whose line contains `AUDIO_PB{N}_CONTROLLER:` | Entry missing, card empty, card differs, or codec differs | Skip when `aplay` is missing; not emitted when `AUDIO_PLAYBACK_COUNT` is `0` |
| `L-AUDIO-RECORDING-DEV-${label}` | | `arecord -l` contains an entry whose card and codec match `AUDIO_CAP{N}_CARD` and `AUDIO_CAP{N}_CODEC`, and whose line contains `AUDIO_CAP{N}_CONTROLLER:` | Entry missing, card empty, card differs, or codec differs | Skip when `arecord` is missing; not emitted when `AUDIO_CAPTURE_COUNT` is `0` |
| `L-AUDIO-PLAYBACK-F` | ✓ | — | — | Always emitted as skip |
| `L-AUDIO-RECORDING-F` | ✓ | — | — | Always emitted as skip |

## Running locally

```sh
cd automated/linux/audio
AUDIO_PLAYBACK_COUNT=1 \
AUDIO_PB0_CARD=imxaudio \
AUDIO_PB0_CONTROLLER=0 \
AUDIO_PB0_CODEC=wm8960-hifi \
AUDIO_CAPTURE_COUNT=1 \
AUDIO_CAP0_CARD=imxaudio \
AUDIO_CAP0_CONTROLLER=0 \
AUDIO_CAP0_CODEC=wm8960-hifi \
bash audio.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for
`L-AUDIO-PLAYBACK-DEV-*` and `L-AUDIO-RECORDING-DEV-*`, including the raw
`aplay -l` or `arecord -l` output and expected/found card and codec values.
LAVA surfaces these logs alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-AUDIO-PLAYBACK-DEV-*` skips | `aplay` is not installed on the target |
| `L-AUDIO-RECORDING-DEV-*` skips | `arecord` is not installed on the target |
| Device check fails with an empty found card/codec | The expected card/controller combination did not match any `aplay -l` or `arecord -l` line |
| Functional tests always skip | Playback/recording loopback is not automated by this script |
