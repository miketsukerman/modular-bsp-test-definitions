# pwm (`adv-pwm`)

PWM checks: configured PWM chips exist under `/sys/class/pwm/`, optional bus
controllers are present, and an optional backlight sysfs device exists.

* **Definition:** [`automated/linux/pwm/pwm.yaml`](../../automated/linux/pwm/pwm.yaml)
* **Script:** [`automated/linux/pwm/pwm.sh`](../../automated/linux/pwm/pwm.sh)

## Scope

**Covered**

* `/sys/class/pwm/<chip>` exists for each configured PWM instance.
* Optional controller discovery through `chk_bus`: PCI devices are matched with
  `lspci`; SoC PWM devices are matched below `/sys/devices/platform/`.
* Optional backlight device path exists.

**Not covered**

* Exporting PWM channels, setting period/duty cycle, or validating output
  waveforms electrically.
* Backlight brightness read/write behaviour; only the configured path is tested.

## Prerequisites

* **Hardware:** configured PWM chips exposed by the BSP under `/sys/class/pwm/`.
  If `PWM_BACKLIGHT_DEV` is set, that backlight device must also be present.
* **Target tools:** `lspci` is required only for instances whose bus is `pci`.
  SoC checks use standard shell tools and sysfs.
* **Root:** not normally required for these existence checks, but may be needed
  on images with restrictive sysfs permissions.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `PWM_COUNT` | `"1"` | Number of PWM chips to iterate over (`pwm0` … `pwm<COUNT-1>`) |
| `PWM{N}_DEV` | `pwmchip0` | sysfs chip name under `/sys/class/pwm/` |
| `PWM{N}_BUS` | `"soc"` | Bus type for PWM `N` (`soc` or `pci`) |
| `PWM{N}_BUS_ID` | `""` | Bus address/ID; empty = controller check not emitted |
| `PWM{N}_REFERENCE` | `""` | Human reference only; not read by `pwm.sh` |
| `PWM_BACKLIGHT_DEV` | `""` | Backlight sysfs path, for example `/sys/class/backlight/backlight`; empty = check not emitted |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

`PWM{N}_REFERENCE` is generated for board metadata but the script does not use
it when deciding pass or fail.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `pwm<N>` for instance
`N`.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-PWM-DEV-${label}` | | `/sys/class/pwm/<PWM{N}_DEV>` exists | sysfs entry missing | Always emitted for each `PWM_COUNT` instance |
| `L-PWM-CONTROLLER-${label}` | | `chk_bus` finds the configured PCI or SoC controller | Controller not found, unsupported bus type, or required lookup fields do not match | Not emitted when `PWM{N}_BUS` or `PWM{N}_BUS_ID` is empty |
| `L-PWM-BACKLIGHT-BRIGHTNESS-DEV` | | `PWM_BACKLIGHT_DEV` path exists | Path missing | Not emitted when `PWM_BACKLIGHT_DEV` is empty |

## Running locally

```sh
cd automated/linux/pwm
PWM_COUNT=1 \
PWM0_DEV=pwmchip0 \
PWM0_BUS=soc \
PWM0_BUS_ID=30660000 \
PWM_BACKLIGHT_DEV=/sys/class/backlight/backlight \
bash pwm.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for emitted
`L-PWM-DEV-*`, `L-PWM-CONTROLLER-*`, and `L-PWM-BACKLIGHT-BRIGHTNESS-DEV`
checks, each ending in a `RESULT:` line. LAVA surfaces these logs alongside the
test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-PWM-DEV-*` fails | Wrong `PWM{N}_DEV`, PWM driver not loaded, or the chip is named differently under `/sys/class/pwm/` |
| `L-PWM-CONTROLLER-*` fails on PCI | `PWM{N}_BUS_ID` does not match `lspci` output, or `lspci` is missing |
| `L-PWM-CONTROLLER-*` fails on SoC | Bus ID or PWM sysfs name does not match the platform sysfs layout |
| `L-PWM-BACKLIGHT-BRIGHTNESS-DEV` fails | Backlight driver not loaded, or `PWM_BACKLIGHT_DEV` points to the wrong path |
