# spi (`adv-spi`)

SPI checks: configured `spidev` device node presence, read/write access, and a
functional `spidev_test` loopback transfer on each configured SPI device.

* **Definition:** [`automated/linux/spi/spi.yaml`](../../automated/linux/spi/spi.yaml)
* **Script:** [`automated/linux/spi/spi.sh`](../../automated/linux/spi/spi.sh)

## Scope

**Covered**

* `/dev/spidevX.Y` exists and is a readable/writable character device.
* `spidev_test -D <device>` can run successfully for the configured device.

**Not covered**

* Electrical signal quality, bus timing margins, chip-select behaviour, or
  transfers to a real peripheral.
* SPI loopback wiring setup; the script assumes MOSI and MISO are already
  bridged for the functional test.

## Prerequisites

* **Hardware:** physical SPI loopback wiring from MOSI to MISO on every device
  that should pass the functional loopback test.
* **Target tools:** `spidev_test`; if absent, the functional loopback test is
  emitted as `skip`.
* **Root:** required when the `spidev` character device is not accessible to the
  test user.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `SPI_COUNT` | `"1"` | Number of SPI devices to iterate over (`spi0` … `spi<COUNT-1>`) |
| `SPI{N}_DEV` | `/dev/spidev0.0` | Character device node for SPI device `N` |
| `VERBOSE` | `"0"` | `"1"` enables per-test-case diagnostic logs |

`SPI{N}_DEV` is mandatory for each configured device. If a device-node check
fails, the loopback test for that device is not emitted.

## Test cases

IDs are shown in sanitised (LAVA) form. `${label}` is `spi<N>` for device `N`.

| Test case ID | Functional | Pass | Fail | Skip / not emitted |
|--------------|:----------:|------|------|--------------------|
| `L-SPI-DEV-${label}` | | Device node exists and is a read/writable char device | Node missing or not R/W (loopback for this device is abandoned) | — |
| `L-SPI-DEV-TEST-F-${label}` | ✓ | `spidev_test -D <device>` exits 0 | `spidev_test` exits non-zero | `skip` when `spidev_test` is missing; not emitted when the device-node check failed |

## Running locally

```sh
cd automated/linux/spi
SPI_COUNT=1 \
SPI0_DEV=/dev/spidev0.0 \
bash spi.sh
cat output/result.txt
```

## Verbose logging

With `VERBOSE=1` the script writes `output/<test-case-id>.log` for
`L-SPI-DEV-*` and `L-SPI-DEV-TEST-F-*`, including the `spidev_test` output for
loopback checks, each ending in a `RESULT:` line. LAVA surfaces these logs
alongside the test result.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `L-SPI-DEV-*` fails | Wrong device path, missing `spidev` node, or insufficient permissions |
| `L-SPI-DEV-TEST-F-*` skips | `spidev_test` is not installed on the target image |
| `L-SPI-DEV-TEST-F-*` fails | MOSI/MISO loopback is missing, the wrong SPI device was selected, or the controller driver cannot complete transfers |
